# Ralph Progress Log
Started: 2026-01-28

## Codebase Patterns
- Game engine: Phaser 3.80+ with TypeScript
- Resolution: 320x200 native, dynamic integer scaling (1x-4x+) based on viewport
- Scaling utility: src/utils/PixelScale.ts handles integer scale calculation and resize events
- Interface: SCUMM-style verb bar (WALK, LOOK, TALK, USE, TAKE, GIVE)
- Pixel art: VGA-style 256 colors, nearest-neighbor scaling
- Pattern puzzles use 7 elements (colors, tones, shapes) representing base-7 mathematics
- No player death or dead ends (LucasArts style)
- Source novel: the_smallest_ambassador_rev7.md
- Scenes are separate files in src/scenes/ importing from src/constants.ts
- Scene transitions use this.scene.start('SceneKey') to switch scenes
- Asset paths: relative to public/ folder (e.g., 'assets/sprites/character.png')
- Asset loading: this.load.image() in preload(), this.add.image() in create()
- UI systems: src/systems/ directory for reusable game systems (VerbSystem, etc.)
- UI events: Use scene.events.emit('name', data) for decoupled UI communication
- UI layout (320x200): Viewport (120px, Y=0-120), Inventory (40px, Y=120-160), Sentence (16px, Y=160-176), Verb bar (24px, Y=176-200)
- Inventory events: 'inventory:selected', 'inventory:deselected', 'inventory:look', 'inventory:changed'
- Item definitions: src/data/items.ts contains ITEM_DEFINITIONS, ITEM_COMBINATIONS, and lookup functions
- Combination events: 'combination:success' (ItemDefinition), 'combination:fail' (source, target InventoryItem)
- Combination keys: "sourceId+targetId" format, register both orderings for bidirectional support
- Room data: src/data/rooms/ directory with types.ts (interfaces), per-room data files, and index.ts barrel (registry + getRoom())
- Room registry: ROOMS record in src/data/rooms/index.ts — add new rooms here when created
- Room loading: GameScene.loadRoom(roomId) clears previous background and renders new room's background at depth -1
- Room accessor: GameScene.getCurrentRoom() returns current RoomData or null
- Hotspot bounds: Use 'rect' (x,y,width,height) or 'polygon' (points array) for collision shapes
- Hotspot responses: Per-verb responses (look/use/take/talk/walk) — string for text, HotspotCallback for actions
- Hotspot entities: src/entities/Hotspot.ts wraps HotspotData into Phaser Zone with interactive hit area
- Hotspot events: 'hotspot:hover' (name), 'hotspot:leave', 'hotspot:click' (HotspotData), 'hotspot:action' (action, data)
- Hotspot lifecycle: GameScene.loadRoom() creates Hotspot entities; clearHotspots() destroys them on room change
- Verb-to-response mapping: VERB_TO_RESPONSE_KEY in Hotspot.ts maps Verb enum to HotspotResponses keys
- Exit zones: Created separately from hotspots in GameScene; emit hotspot:hover/leave events for sentence line
- Room transitions: transitionToRoom() uses camera.fadeOut(500) → loadRoom → camera.fadeIn(500) with isTransitioning guard
- Camera fade events: 'camerafadeoutcomplete' and 'camerafadeincomplete' for chaining transition steps
- Character entities: src/entities/Character.ts base class, src/entities/Player.ts extends it
- Character origin: (0.5, 1) bottom-center — Y position represents feet on ground
- Depth sorting: sprite.setDepth(y) for Y-based ordering; update on every setPosition()
- Sprite sheets: this.load.spritesheet() in BootScene preload(); use PLAYER_CONFIG for asset metadata
- Animation guard: Check anims.exists(key) before anims.create() to avoid duplicate registration
- Player access: GameScene.getPlayer() returns the Player entity
- DialogueSystem: src/systems/DialogueSystem.ts handles dialogue box UI, typewriter, portraits, and click-to-advance
- Dialogue events: 'dialogue:start' / 'dialogue:end' for blocking/unblocking game interaction; 'dialogue:action' for DialogueAction execution
- Dialogue triggering: 'hotspot:action' with action='startDialogue' and data={ dialogueId } triggers DialogueSystem.startDialogue()
- Dialogue blocking: GameScene.isDialogueActive flag blocks handleHotspotClick, handleNPCClick, handleViewportClick, and exit zone clicks
- Speaker portraits: SPEAKER_PORTRAITS registry in src/data/npcs.ts maps speaker names to portrait texture keys + asset paths
- Portrait loading: BootScene iterates SPEAKER_PORTRAITS to preload all portrait images
- NPCDefinition.portraitKey / portraitPath: Each NPC carries portrait asset metadata alongside sprite sheet metadata
- Pattern puzzle system: src/systems/PatternPuzzle.ts defines SACRED_ELEMENTS array (7 elements indexed by base-7 digit)
- Pattern sprite config: PATTERN_SPRITE_CONFIG for texture key, asset path, frame dimensions (follows PLAYER_CONFIG pattern)
- Pattern element data: SacredElement includes index, color, tone, shape, colorHex, colorRGB, toneFrequency
- Pattern enums: PatternColor, PatternTone, PatternShape for type-safe puzzle sequences
- Pattern lookups: getSacredElement(index) returns element by base-7 digit, getElementFrameIndex(element) returns sprite frame
- PatternDisplay: class in src/systems/PatternPuzzle.ts — shows sequence of sacred elements one at a time with tones
- PatternDisplay constructor: new PatternDisplay(scene, elementIndices[]) — indices are base-7 digits (0-6)
- PatternDisplay playback: play() starts sequence, replay() restarts, each element revealed with 500ms delay and Back.easeOut tween
- PatternDisplay audio: Web Audio API oscillator tones at each element's toneFrequency, with gain envelope (300ms duration)
- PatternDisplay events: 'pattern:displayComplete' emitted on scene.events when full sequence finishes playing
- PatternDisplay depth: container at depth 150 (below dialogue at 200, above gameplay)
- Console test helper: window.testPattern([0,2,4]) creates and plays a PatternDisplay in GameScene
